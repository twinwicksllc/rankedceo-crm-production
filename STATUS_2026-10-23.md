## Finding 3: the live CRM `industry_leads` table refuses anonymous inserts, and the lead forms hid the failure

- VERIFIED (query in the CRM project, 2026-10-23): `industry_leads` has row-level security on and exactly one policy, "Users see own leads", `ALL` for `{public}` with `auth.uid() = auth_user_id`. No policy lets `anon` insert, although `20240222000000_create_industry_leads.sql` defines "Public can submit leads". `anon` and `authenticated` hold the table-level INSERT privilege, which does not help while RLS is on.
- VERIFIED (Vercel log, 20:39 UTC): the HVAC lead form failed with `[IndustryLead] Insert failed: 42501 new row violates row-level security policy`. #333 had moved that insert to the anon client on the strength of the repo's migration. That was wrong for the live table.
- The landing quote form works because `app/api/landing/quote/route.ts` uses the admin client, which bypasses row-level security.
- READ: all three lead forms (HVAC, plumbing, electrical) caught a failed submit with an empty `catch` that only wrote to the console, and the page wrappers threw the error, which Next.js turns into an opaque digest in production. A visitor saw neither an error nor a success page.
- Fix (#335): the submit action validates the input on the server with the industry's zod schema, then writes with the admin client; the page wrappers return the failure; the forms show it (`role="alert"`) and still let a successful redirect through. VERIFIED by Tommy on 2026-10-23: the HVAC lead form now reaches the success page, and the test row was deleted by id. Copilot's finding on #335 (the operator id in the share link chose the account) is fixed in the same PR by `lib/services/lead-operator.ts`.
