# Copilot Review Findings Catalog

Source: 133 top-level Copilot review comments across 36 PRs (#188 to #275), read by hand on 2026-10-12. The review comments API reports the author login as `Copilot`; the count grows as new PRs are reviewed, so re-running the command at the bottom returns more than 133 rows.
The goal is to stop repeat findings before Copilot sees them. Each theme lists what Copilot flagged, example PRs, and the rule that prevents it.

How to use: read the checklist in `.github/pull_request_template.md` before you push. Add a row here when a new theme shows up in 2 or more PRs.

Note: PR numbers are examples, not complete lists. Keyword counts over the raw comments overlap heavily, so the themes below come from a manual read.

## What the tools can already catch

Themes 6, 2 (partly), 13 (partly) and 11 (partly) can be caught by typecheck, lint and tests. The `npm run check` script and the CI workflow that runs it (`.github/workflows/ci-checks.yml`) are added by the E1 PR (#277); until that is merged, run `npx tsc --noEmit && npm test` before pushing. Accessibility (theme 2) is now partly enforced by the `jsx-a11y` recommended rules in `eslint.config.mjs`: a changed file may not get more errors of any of those rules than it had on `main`. Two stricter checks were added after reviews found gaps in the stock rules (#282, #283): a `no-restricted-syntax` selector that fails a `<label>` with no `htmlFor` and no wrapped control (the stock rule skips labels whose text mixes `{" "}` with nested elements), and `jsx-a11y/anchor-is-valid` with `components: ["Link"]` plus a second selector that fails a placeholder `href` inside a data object such as `{ label: "Blog", href: "#" }` (the stock rule only reads literal JSX hrefs). In-page fragment links (`#services`) and the website-builder button default are exempt. Buttons and links that contain only an icon must have `aria-label` (`title` alone does not count): the stock `control-has-associated-label` never flags them, so a local rule `local/icon-only-control` in `eslint.config.mjs` does, with its own test in `lib/a11y/icon-only-control.test.ts`. `next build` typechecks every `.ts` file, including `*.test.ts`, and the production Vercel build does not have devDependencies, so a source file that imports one (for example `eslint`) passes `npm run check` but fails the deploy; `lib/ci/no-dev-imports.test.ts` fails first and names the file. Modal keyboard access is checked by `lib/a11y/modal-escape.test.ts`: any file with `aria-modal` must register an Escape handler (use `hooks/use-escape-key.ts`); the test reads the syntax tree, so a comment or string that mentions Escape does not count. A `<label>` must not contain a `<button>` or link (invalid nested interactive markup, found by review on #284): a second `no-restricted-syntax` selector fails it. A backdrop marked `role="presentation"` is skipped by the stock click rules, so that test and your own read of the diff are the check; do not use `role="presentation"` on anything that is the only way to do an action. It does not check everything (for example `aria-hidden` on decorative icons, or role and `aria-modal` on modals, still need the checklist). The rest need the PR template checklist.
