## How the react-hooks errors were fixed

The work followed a small number of repeatable patterns rather than one-off
edits, which is why it landed in a single PR:

- **`set-state-in-effect` (26).** Fetch-in-effect sites now set state only in
  promise callbacks, guarded by a `cancelled` flag; the loading flag is set in
  the event handler that triggers a refetch, or derived from the inputs the
  data was fetched for. Browser-only values (a mounted flag, the query string,
  the stored theme, `matchMedia`) go through `useSyncExternalStore` via two new
  shared hooks, `useIsClient` and `useClientValue`.
- **`immutability` (10).** Loaders that mutated props or module state were moved
  into the effect that uses them.
- **`purity` (6).** `Math.random()` calls were moved into lazy `useState`
  initialisers.
- **`refs` (1).** The website builder's initial draft is now kept in state
  instead of a ref.

## New shared files introduced by #288 (all on main)

- `hooks/use-is-client.ts` — `useIsClient()`, built on `useSyncExternalStore`
  with a server snapshot of `false` and a client snapshot of `true`.
- `hooks/use-client-value.ts` — `useClientValue(getClientValue, serverValue)`
  for browser-only values such as the query string and the stored theme.
- `hooks/use-mobile.ts` — rewritten to `useSyncExternalStore(subscribe,
  getSnapshot, getServerSnapshot)` on `matchMedia('(max-width: 767px)')`, with
  a server snapshot of `false`.
- `components/ui/use-mobile.tsx` — previously a byte-identical copy of the
  hook; it now simply re-exports from `@/hooks/use-mobile`.
- `lib/navigation.ts` — `hardNavigate(url)`, which wraps the intentional
  full-page navigations (after sign-in / sign-out and the OAuth connect
  endpoint) and documents why they are not `router.push`.
