## Cutover blockers found (READ from code; not fixed)

1. `app/api/landing/quote/route.ts`: the quote form's insert into `industry_leads` cannot work as written, for any industry.
   - The smile pool id (`:11`) is `…0000-0004-…`, but WaaS seeds `…4000-a000-…0004`.
   - The insert (`:86-96`) writes `customer_name`, `customer_email`, `customer_phone`, `zip_code`, `preferred_contact_method`, `notes` and `service_details`. `waas/030` defines `industry_leads` with `lead_name`, `lead_email`, `lead_phone`, `problem_description` and `metadata` instead, so PostgREST rejects the unknown columns.
   - 030 was generated from the live CRM shapes, and CRM migration `20240301000005_standardize_industry_leads_columns.sql` renamed the columns to `lead_*`. So the form is probably already failing in production (READ, not tested).
   - Fixing the id alone does not unblock it; the insert's columns must change too.
2. `app/api/agent/chat/route.ts:18`: the default account `…4000-a000-…0001` exists in no migration. It is fixed by setting `DEFAULT_ACCOUNT_ID` or by changing the default. Whether `DEFAULT_ACCOUNT_ID` is set in Vercel is not verified.
3. `lib/actions/smile-assessment.ts:74,102` filter `users.auth_user_id`, a column the WaaS `users` table doesn't have. The error is ignored, so assessments silently land in the pool account.
4. Several stats queries name columns that do not exist (`activities.status`/`due_date`, `companies.status`, `industry_leads.estimated_value`, `deals.source`, `campaign_emails.opens`/`clicks`). They are probably already failing in production; not verified.
